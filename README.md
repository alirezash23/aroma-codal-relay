# Aroma Codal Relay

سرویسی که اطلاعیه‌های کدال را برای شرکت‌های تحت پوشش آروما جمع می‌کند و به صورت JSON تحویل می‌دهد.

**اینجا هیچ تحلیلی انجام نمی‌شود.** وظیفه این مخزن فقط تأمین ماده خام تمیز است: اطلاعیه تاریخ‌دار، لینک‌دار، با تیپ شرکت و برچسب حقوق بازنشر. تحلیل جای دیگری انجام می‌شود.

## ساختار

| فایل | کار |
|---|---|
| `codal.py` | هسته — واکشی، پاک‌سازی، تاریخ شمسی، dedupe، fallback تلگرام |
| `main.py` | API با FastAPI (برای لیارا) |
| `snapshot.py` | اجرای مستقل بدون سرور (برای GitHub Actions) |
| `companies.json` | ۱۸ شرکت + قواعد هر تیپ شرکت |
| `.github/workflows/daily-snapshot.yml` | اجرای روزانه، نتیجه در `data/` کامیت می‌شود |

## Endpointها

```
GET  /health                      وضعیت سرویس
GET  /v1/companies                لیست شرکت‌ها و قواعد تیپ
GET  /v1/today                    اطلاعیه‌های امروز
GET  /v1/latest?days=30           بازه دلخواه
GET  /v1/important?days=7         فقط اطلاعیه‌های مهم
GET  /v1/symbol/زاگرس?days=30      یک نماد + قواعد تیپ همان شرکت
POST /v1/reload                   بارگذاری مجدد companies.json
GET  /debug                       عیب‌یابی — کدام منبع جواب می‌دهد
```

پارامتر `with_body=true` متن کامل اطلاعیه را هم می‌کشد. کندتر است ولی برای راستی‌آزمایی عددی لازم است.

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `API_KEY` | خالی | اگر ست شود، هدر `X-API-Key` اجباری می‌شود |
| `CACHE_TTL` | `900` | ثانیه |
| `MAX_WORKERS` | `6` | تعداد درخواست موازی |
| `TELEGRAM_ENABLED` | `1` | `0` یعنی fallback تلگرام خاموش |

روی لیارا حتماً `API_KEY` را ست کن — آدرس سرویس عمومی است.

## قواعدی که از سند v4.0 به کد آمده‌اند

**تیپ شرکت روی هر آیتم می‌آید.** یوتیلیتی (`مبین`، `بفجر`) در `type_rules` مقدار `global_benchmarks: false` دارد؛ درآمدشان قراردادمحور است نه کالامحور، پس بنچمارک جهانی برایشان موضوعیت ندارد. این داده است، نه توصیه در پرامپت.

**برچسب حقوق بازنشر.** هر آیتم فیلد `rights` دارد: `free_full` (کدال، TSETMC، IEA، EIA، اوپک)، `concept_only` (آرگوس، ICIS، پلتس، وود مکنزی — بدون رقم)، `rewrite_required` (خبر و تلگرام).

**تلگرام مسیر موقت است، نه منبع.** آیتم‌های تلگرامی فیلد `warning` دارند: در متن به «اطلاعیه کدال» ارجاع بده نه به کانال، و هر عدد در اولین فرصت با خود سند تطبیق داده شود.

**متن کامل سند، نه فقط عنوان.** قواعد راستی‌آزمایی (اتحاد موجودی، قاعده مخرج، زنجیره تخصیص سود) روی بدنه سند کار می‌کنند. `with_body=true` بدنه و جدول‌ها را می‌آورد.

## اجرا

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

اسنپ‌شات مستقل:

```bash
python snapshot.py --days 1
python snapshot.py --days 7 --with-body
```

## نکاتی که هنوز تأیید نشده‌اند

این کد بدون دسترسی به کدال نوشته شده. سه چیز باید با خروجی واقعی تطبیق داده شود:

1. **سلکتورهای `fetch_body`** — اگر `body_status` برابر `empty` برگشت، ساختار صفحه اطلاعیه عوض شده و سلکتورها باید اصلاح شوند.
2. **`IMPORTANT_KEYWORDS`** — فعلاً کلیدواژه‌محور است. بعد از دیدن `letter_code` واقعی، فیلتر را روی کد اطلاعیه ببر که دقیق‌تر است.
3. **`products` در `companies.json`** — با گزارش فعالیت ماهانه هر شرکت تطبیق بده و اصلاح کن.

مسیر تست: `/health` → `/debug` → `/v1/today`

## گزارش اولین اجرای واقعی — 1405/05/26

اجرا روی GitHub Actions، ۱۸ نماد، بازه یک روز.

**نتیجه:** سرورهای گیت‌هاب به `search.codal.ir` نمی‌رسند — هر ۱۸ نماد `ConnectTimeout` گرفت. مسیر Actions برای کدال بسته است و `cron` خاموش شد. مسیر اصلی، سرور داخل ایران است.

**باگی که این اجرا لو داد:** تطبیق نماد در متن تلگرام سه انتساب غلط ساخت — «خراسان» داخل `#اخشان_خراسان` و «بوعلی» داخل `#سرمایه_گذاری_بوعلی` مچ شده بودند. علت: مرز کلمه فقط با حروف فارسی چک می‌شد و `_` حرف فارسی نیست.

اصلاح در `match_symbol`: فقط هشتگ دقیق نماد یا نام کامل شرکت پذیرفته می‌شود، و برای هشتگ زیرخط دست‌نخورده می‌ماند تا `#جم_پیلن` با `#جم` اشتباه نشود. روی همان سه پست تست شد: هر سه حالا رد می‌شوند. آیتم‌های تلگرامی فیلد `matched_by` گرفتند تا مسیر تطبیق قابل ردیابی باشد.

**سیگنال صادقانه:** `snapshot.py` حالا اگر فقط تلگرام جواب داده باشد کد خطا برمی‌گرداند. تلگرام مسیر موقت است، نه منبع — اجرا نباید با داده fallback سبز شود.
